# 편지의 대화 오독 수정 — 2026-09-09

이전 검증에서 남은 두 오류는 실제 대화의 화자를 바꾸어 해석한 것이다. 리오의 영화 선택을 루의 선택으로 간주하고, 둘이 잘못된 회상에 동의했다는 이유로 ‘솔직한 취향 변경’이라고 추천했다. 다른 편지는 루가 말한 발소리를 리오의 관찰로 옮겼다. 발화자 이름을 프롬프트에 강조하는 것만으로는 해결되지 않았다.

## 변경한 처리

1. 에이전트가 자기 소유자의 비공개 정보와 공개 대화로 편지 초안을 만든다.
2. 저장될 길이와 형태로 먼저 정리한다. 잘못된 인용 위치나 필수 필드 누락은 차단한다.
3. 별도의 사실 검증 요청이 대화 전체를 시간 순서대로 읽고 초안의 모든 필드를 대조한다. 실제 사용자 ID로 구분한 ‘내 발화/상대 발화’를 사용하며 ID 자체는 모델에 보내지 않는다.
4. 오류가 있으면 원문·실패한 초안·구체적인 수정 사항을 주고 한 번 다시 작성한다. 수정은 Sol 모델에 맡긴다.
5. 수정한 내용도 독립된 요청으로 다시 검사한다. 통과한 내용만 편지와 다음 탐색의 교훈에 사용한다.

검사 범위에는 제목, 인용할 대화, 본문, 소유자에게 하는 질문, 추천 여부, 후속 질문, 다음 탐색의 교훈, 공개 요약·좋았던 점·마찰이 모두 포함된다. 본문에서 지운 잘못된 전제가 질문이나 기억에 남는 것도 실패다.

원문에서 실제로 말한 내용과 나중에 주장한 회상을 구분한다. 같은 사람이 실제로 두 선택을 했는지, 가정을 실제 과거로 바꿨는지, 제안을 이미 실행한 일로 썼는지, 답하지 않은 질문에 답했다고 썼는지, 부정 표현이나 관계 목적을 바꿨는지 확인한다. 공유 필드는 공개 대화에만 근거해야 한다. 상대방의 비공개 기억이나 판단은 검증 요청에도 전달하지 않는다.

## 실패 처리는 어떻게 되는가

- 초안은 최대 두 번, 각각에 대한 검증도 최대 두 번이다. 무한 재작성하지 않는다.
- 검증 및 수정 모델은 `gpt-5.6-sol`로 지정한다. 검증할 수 없을 때 임의의 저가 모델로 대체해 승인하지 않는다. 각 요청에는 90초 제한을 둔다.
- 검증기가 응답하지 않거나 출력 형식이 잘못됐거나 두 번째 초안도 실패하면 미검증 편지를 반환하지 않는다.
- 한쪽만 통과해도 그 만남으로 두 사람을 소개하지 않는다. 대화는 남기고 탐색은 계속한다. 잘못된 본문·추천·교훈은 저장하거나 메일로 보내지 않는다.
- 양쪽 검증 요청이 모두 끝나기 전에 액션이 반환되어 남은 요청이 버려지던 경로도 정리했다.
- `aiRuns`에 작성과 사실 검증을 분리해 기록한다. 오류가 있는 초안은 성공한 편지로 기록하지 않는다. 이 기록은 내부용이며 앱이나 이메일에 노출하지 않는다.

## 실제 모델 회귀 검증

원본은 이전 [관계 목적 검증](RELATIONSHIP_GOALS_REVIEW.md)의 실패 자료에서 가져왔다. 오류 원문을 좋은 내용으로 덮어쓰지 않았다. 다음 예상 결과를 먼저 정하고 실행했다.

| 사례 | 기대 결과 | 최종 Sol 검증 |
| --- | --- | --- |
| 실제 영화 선택 오류 원본 편지 | 차단 | 차단 |
| 실제 발소리 화자 오류 원본 편지 | 차단 | 차단 |
| ‘독점 관계를 원하지 않는다’를 원한다고 요약 | 차단 | 차단 |
| 마지막 질문에 상대가 답했다고 작성 | 차단 | 차단 |
| 가상의 계란 실수를 실제 과거로 작성 | 차단 | 차단 |
| 실제 가벼운 만남 의도 확인에 근거한 편지 | 통과 | 통과 |
| 실제 친구 관계 의도 확인에 근거한 편지 | 통과 | 통과 |

초기 검증 실행에서는 긴 오류 설명이 잘리면서 기존 공통 모델 대체 경로가 `gpt-4.1-mini`까지 내려가 영화 선택 오류를 잘못 승인했다. 그 실패도 보존했다. 검증기의 출력 예산을 늘리고 자동 모델 대체를 금지한 최종 실행은 **5개 오류 차단·2개 정상 통과**다. 정상 사례는 원본 대화에 맞게 별도로 작성한 대조 편지다.

실패했던 대화 두 개에서 각자의 편지 네 개를 실제 작성·검증 경로로 다시 생성했다.
네 편지 모두 통과했고, 잘못된 급선회나 발소리 화자 해석을 추천 근거로 쓰지 않았다.
서로 명시한 관계 목적과 실제로 주고받은 제안을 중심으로 편지가 나왔다.
기존 날짜의 원문·판단·사람의 결정은 덮어쓰지 않고 별도 결과로 보존했다.

새 가상 계정 두 개로 정상 탐색도 실행했다. 6마디 뒤 한쪽 초안이 ‘상대가 먼저
제안했다’는 과장과 공동 제안 범위 오류로 거절됐다. Sol이 수정한 편지를 Sol의 별도
검증 요청이 통과시킨 뒤 양쪽 편지가 저장됐다. 최종 두 에이전트는 추천했고,
두 사람의 동의는 미결정이며 연락처는 비공개다. 실제 저장된 전달 문맥으로 메일
HTML과 텍스트도 생성해 인용·본문·질문이 검증된 내용인지 확인했다. 발송은 하지 않았다.

자동 회귀 테스트는 수정 후 재검사, 두 번 실패 후 보류, 정상 초안의 불필요한 재작성 방지, 저장될 문구와 검사된 문구의 동일성, 같은 이름의 두 화자, 잘못된 인용 위치, 검증 응답 누락·모순·존재하지 않는 발화 인용, 검증 서비스 실패·모델 대체 차단·시간 초과를 다룬다. 백엔드 테스트에서는 한쪽 실패 뒤 양쪽 소개·이메일·학습 기록이 생성되지 않고 기존 원문과 사람의 결정이 보존되는 것을 확인한다.

최종 **37개 파일·328개 테스트**, 타입 검사를 포함한 빌드, 린트가 통과했다.
실제 로컬 서버에도 반영했고 임시 검증용 내부 액션은 제거했다.

## 적용 범위와 증거

- 격리된 로컬 Convex `127.0.0.1:3210`에 반영했다. 클라우드 개발·운영 배포는 하지 않았다.
- 모든 가상 계정은 이메일 알림이 꺼져 있다. 실제 사용자에게 메일을 보내지 않았다.
- [오류·정상 사례, 검증 결과, 재작성, 새 만남 JSON](qa/2026-09-09-letter-grounding.json)
- 상세 실행 자료는 Git에서 제외한 `.scratch/letter-grounding/`에 있다. 추적되는 증거에는 인증 토큰을 포함하지 않는다.

검증 모델도 모든 가능한 의미 오류를 수학적으로 증명하는 장치는 아니다. 이번에 발견한 오류가 실제로 차단되고 정상 편지가 통과하는지, 검증 실패가 사용자에게 잘못된 추천이나 기억으로 전달되지 않는지를 각각 검증한다. 추가 모델 호출 때문에 편지 작성에는 검증 시간이 더 든다.
