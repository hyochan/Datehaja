## 같은 사용자로 이어간 과정

## 검증에서 발견해 고친 문제

- **프로필 재저장 시 기억 초기화:** 기존 에이전트에 온보딩 정보를 다시 저장해도 배운 기억을 보존한다.
- **응답 순서 경합:** 답변의 원본 사용자 메시지와 읽었던 상태를 저장 직전에 다시 확인한다. 늦은 답변과 중복 콜백은 새 정정을 덮어쓰지 않는다. 그 사이 데이트 교훈이나 사용자 설정이 바뀌면 다시 읽고 응답한다.
- **피드백과 다음 만남 경합:** 어느 쪽이든 피드백을 정리 중이면 새 만남을 먼저 확정하지 않는다.
- **사용자 정정과 에이전트 추측의 혼합:** 사용자 기억과 데이트 관찰을 별도로 유지한다. 다음 발화·판단에는 누적 기억과 최근 사용자 원문 3개를 자기 에이전트에게만 전달한다. 모델이 요약에 실패해도 원문은 다음 만남에 전달된다.
- **오래된 제안 적용:** 새 피드백이나 명시적인 브리프/취향 편집 뒤에는 이전 제안을 `superseded`로 닫는다. 폐기된 버튼을 나중에 눌러도 적용되지 않는다. 승인·거절 결과도 다음 대화에 전달한다.
- **사용자 반응 오독:** 최초 nano 응답이 ‘면접 같아 싫었다’를 자신의 긍정적인 소감으로 대체했다. 피드백 모델을 Luna 우선으로 바꾸고, 사용자 원문을 마지막에 배치하며, 제안 이유가 실제 사용자 발언에 근거하도록 고쳤다. 잘못된 최초 응답은 증거에 그대로 남겼다.
- **허구의 사용자 이력:** 발화에 사용자 습관·과거를 넣을 때 자기 브리프의 근거를 함께 생성하고 검사한다. 근거가 없으면 저장 전에 한 번 다시 작성한다. 근거 없는 반복 실패는 대화를 실패로 보존한다. 가상 상황의 선택과 실제 과거를 구분한다.
- **연장 데이트의 마지막 말 누락:** 피드백 문맥에 처음 6마디만 전달하던 문제를 고쳐 최대 10마디 전체를 읽는다.

## 반복 검증의 범위

`bun run test convex/agentLearning.test.ts convex/lib/ownerFacts.test.ts`로 새 회귀 시나리오를 실행할 수 있다. 전체 검증은 `bun run test`, `bun run build`, `bun run lint`다.

새 테스트는 같은 시각의 연속 정정, 오래된/중복 콜백, 추론 중 새 교훈 및 브리프 편집, 재온보딩 기억 보존, 피드백 완료 전 양방향 배정 차단, 승인·거절에 따른 실제 다음 후보 차이, 다른 사용자 기억 격리, 모델 실패, 연장 대화의 마지막 말, 근거 없는 발화의 재작성, 180일·36명 이후 기억과 과거 만남 보존을 포함한다.

새 로그인 세션과 새로고침 후 기억·승인한 조건이 유지되는 것을 브라우저에서도 확인했다. 390px 화면에 가로 넘침이 없고, 미매칭 화면에 소개 승인 버튼이 없으며, 네 번의 만남 모두 상대의 연락처·사람의 결정·숨은 판단은 비공개였다. 이번 실행에서 만들어진 이메일 기록 6개는 모두 `skipped_preference`다. 로컬 전체 16개 기록 역시 발송된 것이 없다.
