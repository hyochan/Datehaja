# 제출 준비 상태 — 2026-09-09

## 현재 판단

아이디어와 구현 기반에는 경쟁력이 있다. 다만 현재 검증으로 “우승 준비가
끝났다”고 판단할 수는 없다. 경쟁 출품작과 실제 심사 결과를 알 수 없으므로
승률이나 임의의 점수를 붙이지 않는다. **같은 소유자의 피드백이 다음 실제 생성 데이트로 이어지는 모습**은 이제
공개 비교 화면과 54초 시연으로 확인할 수 있다. 생성 품질의 일관성과
실사용자 검증은 여전히 과제다.

[공식 심사 기준](https://www.convex.dev/hackathons/all-gas)을 2026-09-09에
다시 확인했다. 창의성과 실제 유용성, Convex 활용 깊이, 스폰서 도구의 실제
작동, 접근 가능한 공개 앱, 소셜 반응, 3분 미만 실제 제품 시연을 본다.
테스트 개수는 생성 대화의 자연스러움이나 실제 사용성을 증명하지 않는다.

## 확인된 강점

- 한 번 시작하면 계속 찾는 탐색, 실제 저장 대화, 각자의 편지와 두 사람의
  독립적인 동의가 구현되어 있다. 무조건 매칭하거나 정기 메일을 만드는 구조를
  제거했고, 미매칭은 앱에서 실제 상태를 보여준다.
- 자기 말투 교정과 상대에 대한 반응을 발언에 연결한다. 비공개 기억에 교정을
  누적하고 다음 데이트 프롬프트가 읽는다. 피드백은 과거 대화나 상대를 바꾸지 않는다.
- 관계 목적을 양쪽에서 확인한다. 진지한 관계만 우선하지 않으며 가벼운 만남과
  친구 관계도 서로 니즈가 맞는 사람끼리 탐색한다.
- 설명 화면은 만들기 → 자율 데이트 → 이야기 듣기 → 피드백의 네 단계로
  정리했다. 복잡한 기술 도식은 기본적으로 접혀 있다.
- 최신 기능 검증은 40개 파일의 369개 테스트 통과. 문구 변경 후에도 빌드와
  린트가 통과했다. 모바일 320·390px과 데스크톱, 밝고 어두운 테마를 확인했다.

## 우승 경쟁력을 위해 남은 일

1. **생성 품질의 일관성.** 이번 같은 계정의 네 실제 예약 데이트는 56마디다.
   존댓말 교정과 세 번의 피드백 기억은 유지됐다. 두 회고는 처음 오독 검증에서
   보류됐지만, 같은 원문을 다시 처리해 정확한 편지를 복구했다. 지적된 필드만
   수정하고 전체를 재검증하며, 일회성 반응과 일반 취향·동의와 직접 선택을
   구분하도록 보강했다. 원래 잘못된 두 편지는 여전히 거부되고, 수정된 네
   개인 회고는 별도 재검사도 통과했다. `docs/REVIEW_RECOVERY.md`에 중간
   실패까지 기록했다. 그러나 장면과 농담의 반복이 남으며, 답변 길이가
   줄었다는 근거는 없다. 한 실행을 전체 품질로 일반화하면 안 된다.
2. **핵심 변화의 시연.** `/preview/agent-coaching`에서 첫/최근 발언 비교,
   실제 저장된 피드백·답장·누적 기억, 네 기록 전체, 재검증 후 복구된 회고까지 확인한다.
   `/demo/learning-proof.mp4`는 실제 브라우저 화면을 담은 54초 보조 시연이다.
   How it works의 설명용 예시에서 이 기록으로 연결된다. 기존 전체 제출
   영상은 이전 버전이므로 최종 제출 컷과 공개 링크는 별도로 맞춰야 한다.
3. **처음 쓰는 사람의 확인.** 독립적인 실제 사용자가 설명 없이 시작하고,
   돌아온 대화에서 자신을 알아보며, 피드백 후 변화를 느낀다는 근거가 아직
   없다. 6명 가상 사용자와 180일 자동 시나리오는 유용하지만 이를 대신하지 않는다.
4. **제출본 고정과 공개 증빙.** 최신 변경은 더 이상 작업 트리에만 있지 않고
   저장소에 커밋되어 리뷰를 거친다. 프런트엔드는 `main` 병합 시 Vercel이
   배포하지만 운영 백엔드는 `bunx convex deploy -y`를 따로 실행해야 하며,
   백엔드를 먼저 배포해야 중간에 깨지는 구간이 없다. 제출용
   소스와 배포본을 맞추고, 최종 영상의 공개 링크, 필수 소셜 게시, 제출 완료를
   실제 링크로 확인해야 한다. `submission/SOCIAL.md`는 아직 미게시 초안으로
   표기되어 있다. 별도로 게시되었는지는 이번 검토에서 확인하지 않았다.

## 배포 구분

- 현재 확인한 최신 경험: 개발 `adorable-boar-359`의 백엔드와 프런트엔드.
- 기존 제출 대상: 운영 `merry-bass-190` 및 datehaja.com. 이 작업에서 운영에
  최신 변경을 배포하지 않았다. 공개 HTML과 스타일을 다시 비교했을 때 개발에는
  새 학습 흐름이 있고 운영에는 없다. 이 비교는 프런트엔드 차이의 증거이며
  운영 백엔드 전체 상태를 확인한 것은 아니다.
- 운영 반영, 제출 대상 공개 체험 갱신, 비로그인 전체 경로 확인은 남아 있다.
  이번 품질 변경은 개발 백엔드, 비교 화면과 영상은 개발 프런트엔드에 반영한다.
  공식 페이지는 개발/운영 배포의 구분을 요구하지 않는다. 현재 개발 URL을
  최종 제출 대상으로 선택한다면 그 URL과 소스, 영상의 버전을 고정해 확인하면
  된다. 운영 배포 자체를 별도의 대회 참가 조건으로 해석하지 않는다.
