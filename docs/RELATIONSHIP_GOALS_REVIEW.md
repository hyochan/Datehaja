# 관계 목적에 맞는 매칭 검증 — 2026-09-09

후속 수정: 아래에 보존한 편지 오독은 [별도 사실 검증과 재작성](LETTER_GROUNDING_REVIEW.md)
경로로 보강했다. 원본 오류 2종을 포함한 오류 사례 5개 차단·정상 대조 편지 2개 통과를
확인했다. 아래 ‘남은 문제’는 이 후속 수정 전 실행의 기록이다.

사용자의 기준은 **서로 원하는 관계가 맞는 사람끼리 만나기**다. 진지한 연애, 가벼운 만남, 친구 관계 사이에 우열을 두지 않는다. 진지한 관계를 원하지 않는 사람을 장기 연애로 설득하는 제품도 아니다.

이 변경은 로컬 UI `127.0.0.1:4174`와 격리된 Convex `127.0.0.1:3210`에서만 검증했다. 클라우드 개발·운영 배포는 하지 않았다. 최신 36개 파일의 313개 테스트, 타입 검사를 포함한 빌드, 린트가 통과했다.

## 매칭 기준

| 내가 선택한 목적 | 후보가 될 수 있는 상대의 선택 |
| --- | --- |
| 진지한 관계 | 진지한 관계 |
| 가벼운 만남 | 가벼운 만남, 자연스럽게 알아가기, 아직 알아가는 중 |
| 자연스럽게 알아가기 | 가벼운 만남, 자연스럽게 알아가기, 친구부터 시작, 아직 알아가는 중 |
| 친구부터 시작 | 친구부터 시작, 자연스럽게 알아가기 |
| 아직 알아가는 중 | 가벼운 만남, 자연스럽게 알아가기, 아직 알아가는 중 |

양쪽 모두 이 조건을 만족해야 한다. 어느 한쪽이라도 **같은 관계 목적을 선택한 상대만 만나기**를 켜면 동일한 선택만 허용한다. `open`은 ‘자연스럽게 알아가기’이며 진지한 관계를 약속했다는 뜻이나 비독점 관계의 별도 분류가 아니다. 친구와 가벼운 데이트도 같은 기대라고 가정하지 않는다.

이전에는 목적 차이를 점수로만 반영해 관심사가 같으면 충돌하는 목적의 상대를 배정할 수 있었다. 이제 후보 단계에서 제외한다. 후보 자격이 생겼다고 자동 추천하는 것은 아니다. 실제 대화에서 기대를 확인하고 양쪽 에이전트가 추천한 뒤, 두 사람의 독립적인 동의를 받아야 연락처가 열린다. 맞는 후보가 없으면 탐색 상태로 남는다.

## 6인 실제 모델 실행

관계 목적 외의 관심사 점수로 결과를 설명하지 못하도록 여섯 명 모두 Cooking·Coffee·Films와 같은 성향 태그를 줬다. 서울·한국어·서로 맞는 나이 및 성별 조건을 설정하고, 실제 인증·온보딩·탐색 API를 이용했다. 대화와 판단은 실제 모델이 생성했다.

| 인물 / 에이전트 | 관계 목적 | 실제 배정과 결과 |
| --- | --- | --- |
| 지훈 / 준 ↔ 가은 / 봄 | 진지한 관계 | 6마디, 양쪽 추천 |
| 재이 / 리오 ↔ 서아 / 루 | 가벼운 만남 | 6마디, 양쪽 추천 |
| 우진 / 온 ↔ 유나 / 소라 | 친구 관계 | 6마디, 양쪽 추천 |

세 쌍 모두 사람의 결정은 대기 상태이며 연락처는 비공개다. 가벼운 만남과 친구 관계를 ‘진지하지 않다’는 이유로 낮게 평가하지 않았다. 모든 가상 계정의 이메일 알림은 꺼져 있고 실제 메일을 보내지 않았다. 기존 테스트 계정과 대화는 삭제하지 않고 이전 참가자를 탐색 밖으로 쉬게 했다.

## 피드백 이후에도 적용되는가

자동 테스트에서 같은 후보군에 두고 관계 목적 변경 제안의 승인/거절만 바꿨다. 승인하면 새 목적에 맞는 후보를 선택하고, 거절하면 기존 목적을 유지했다.

추가로 다음 상황을 검증했다.

- 기다리는 도중 목적이 바뀌면 이전 검색 위치부터 그대로 계속하지 않고 새 조건으로 재탐색한다.
- 소개를 기다리며 한 사람만 동의한 상황에서 목적이 충돌하도록 바뀌면 소개를 닫는다. 실제 사람의 동의 기록을 임의의 거절로 바꾸지 않는다.
- 대화 도중 목적이 바뀌었는데 모델이 이전 기준으로 추천해도 소개 알림을 만들지 않는다.
- 연결 직전에도 최신 목적을 확인한다. 이미 두 사람이 동의한 연결은 이 변경으로 해제하지 않는다.
- 쉬고 있는 사람을 설정 변경만으로 탐색에 재참여시키지 않는다.

390px 모바일 브라우저에서 진지한 관계·가벼운 만남·친구 관계 설정 안내, 동일 목적 옵션, 가로 넘침 없음, 상대 비공개 정보 격리도 확인했다. ‘동일 목적만’ 옵션을 끈 상태의 설명도 ‘이 조건으로 후보를 제외하지 않는다’는 모호한 기존 문구 대신, 서로 기대가 맞을 수 있는 선택만 포함한다고 명시했다.

## 생성 품질은 별도로 검토했다

양쪽 추천을 받았다는 사실만으로 대화가 좋다고 판정하지 않았다.

1. 최초 가벼운 만남에서 리오가 자기의 영화 선택을 루가 한 것으로 말했고, 루도 잘못된 전제에 동의했다. 다섯 번째 말에 반드시 놀라운 점을 말하게 하던 지시를 제거하고 발화자 확인·잘못된 전제 정정을 추가했다.
2. 같은 두 인물의 설정으로 새 계정을 만들어 재실행했다. 그 혼동은 없었으나 ‘한 곡 듣고 골목으로 가자’는 약속을 반복했다. 합의한 가상 행동 다음의 장면으로 이어가도록 보강하고 편지의 라운드 번호·평가 용어를 피하게 했다.
3. 다시 새 만남을 실행해 무대에서 골목으로 이동한 뒤 새 질문으로 이어지는 흐름을 확인했다. 하지만 편지 하나는 발소리를 언급한 주체를 여전히 혼동했다. 모델 입력에 실제 사용자 ID로 계산한 ‘내 말/상대 말’을 명시하고, 편지에서는 함께 표시되는 원문 대화를 다시 요약하기보다 자기 반응을 쓰게 보강했다. 사용자 ID 자체는 모델에 보내지 않는다.

세 번의 만남 기록은 모두 그대로 보존했다. 마지막 보강은 오류가 있던 두 원문에 대해 각자의 편지를 다시 생성하는 별도 검증으로 확인하며, 기존 날짜·발화·판단·사람의 결정은 덮어쓰지 않는다. 재생성 결과는 증거의 `reviewRechecks`에 분리한다. 이 재검증은 새로운 데이트 횟수에 포함하지 않는다.

**재검증에도 남은 문제:** 마지막 만남의 ‘발소리’ 오귀속은 새 편지에 나타나지 않았지만,
최초 원문을 다시 읽은 편지 하나는 여전히 잘못된 영화 선택 변경을 근거로 삼았다.
발화자 표식과 프롬프트 보강만으로 의미상 사실 검증이 보장되지는 않는다.
따라서 관계 목적별 배정은 통과, 생성 편지의 사실 정확성은 미해결 품질 항목으로 분리한다.
이 상태를 전체 경험이 완벽하거나 제출 품질 검수가 끝난 상태라고 판정하지 않는다.
