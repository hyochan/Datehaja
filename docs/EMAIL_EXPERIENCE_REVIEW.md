## 후속 실수신 검증: Gmail 이미지 차단

최초 브라우저 검증은 CID 첨부를 data URL로 치환했으므로 실제 수신 환경을
검증한 것이 아니었다. 사용자의 깨진 이미지 제보 뒤 Gmail에서 원본을 직접 열었다.
첨부 PNG 세 개의 바이트는 정상이었지만, 스팸으로 분류된 메일의 HTML 이미지에서
`src`가 제거되어 있었다. Gmail은 과거 스팸과 유사하다는 분류 이유를 표시했다.

이미지 ID를 표준 주소 형식으로 맞춘 수정본을 요청한 동일 주소에 한 통 보냈다.
수정본도 스팸함에서는 동일하게 차단됐다. 해당 테스트 대화를 ‘스팸 아님’으로
옮긴 뒤 **원본과 수정본 모두** 장면(1040px)과 두 캐릭터(각 341px)의 실제 이미지가
로드됐다. 따라서 이 Gmail 실패의 확인된 원인은 스팸 분류이며, ID 형식 변경만으로
해결됐다고 주장하지 않는다. 수정본은 2026-09-09 03:08 KST에 발송 접수됐다.

별도로 이미지 ID와 HTML을 함께 정규화하고, 중복·누락된 참조는 발송 전에
거부하도록 보강했다. ID는 [RFC 2392](https://www.rfc-editor.org/rfc/rfc2392.txt)의
주소 형식을 사용하며 동일 페이로드의 재시도에서도 일관된다. 실제 발송 MIME에서
인라인 PNG 3개와 HTML 참조 5개가 정확히 연결되고 원본 이미지 해시가 보존됨을 확인했다.

이는 요청한 Gmail 계정에서 표시를 확인한 결과다. 다른 실사용자에게 스팸으로
분류되지 않는다는 보증은 아니다. 정식 발신 도메인과 실제 전달률 검증은 제출 전
남은 작업으로 유지한다. 수신 계정의 스팸 필터 전체나 별도의 허용 필터는 변경하지 않았다.
Gmail은 이 대화를 받은편지함으로 옮기며 이 발신자의 향후 메시지도 받은편지함으로
보내겠다고 안내했다. 상세 원본 MIME·수정본·검증 자료는 `.scratch/email-image-fix/`에 있다.
이 보강 후 전체 333개 테스트와 빌드·린트가 통과했다. 코드 보강은 로컬에만 반영했다.

사용자가 요청한 테스트 메일을 준비하면서 사실 검증과 문체를 별도로 점검했다.
기존의 의미 검증 통과만으로 공감되는 편지가 되는 것은 아니었다.

## 바꾼 점

- 인사와 짧은 두 문단을 먼저 읽고, 장면 그림과 실제 인접 발화 두 개를 뒤에서 확인한다.
- 검증된 문단 구분을 HTML과 일반 텍스트 양쪽에 보존한다.
- 큰 판정 카드 대신 서명 옆에 추천 여부를 작게 표시한다.
- 마지막 질문은 상대의 성격을 평가하거나 점수를 매기게 하지 않고, 자신의 느낌이나 취향을 답할 수 있게 한다.
- 편지 작성 모델을 Sol로 올렸다. 실제 생성에서도 반복 서두가 남아, 귀환을 설명하도록 유도하던 지침을 제거했다. 문체 품질을 모든 후속 생성에서 보장한다고 주장하지 않는다.
- 요청한 테스트 편지는 생성본을 직접 편집하고 같은 원문으로 독립 사실 검증을 다시 실행했다. 앱의 저장된 과거 데이트나 사람의 결정을 덮어쓰지 않았다.
- 공개 사이트에 아직 없는 새 장면 이미지는 MIME 인라인 첨부로 넣는다. 명시적인 테스트 편지에는 가상 인물 안내를 표시하고 실제 데이트 열기·동의 버튼을 넣지 않는다.

## 검증

로컬에서 동일한 실제 생성 대화의 두 시점을 세 차례 다시 읽었다. 초기 문체의
반복을 보존했다. 직접 편집한 편지의 재검사에서는 기존 요약이 ‘자유롭게’라는
한 화자의 표현을 양쪽의 공통 의향으로 묶은 부분을 발견했다. 화자별 표현을
섞지 않는 관찰로 수정해 다시 검사했다.

전체 37개 파일·330개 자동 테스트, 빌드와 린트 통과. 마지막 템플릿 수정 후
관련 35개 테스트를 다시 통과했다. 인라인 첨부의 수신자·재시도 키·페이로드,
검증된 문단 보존, 테스트 편지의 실제 데이트 링크 제외를 확인했다.

390px와 900px 너비에서 넘침과 모든 이미지 로딩을 검사하고 실제 화면을 읽는다.
두 화면에서 넘침 없이 모든 이미지가 로드됐고, 최종 화면을 직접 읽었다.
브라우저 검증은 모든 메일 앱의 렌더링을 보증하지 않는다.

2026-09-09 02:54 KST에 사용자가 지정한 주소로 테스트 메일 한 통을 보냈다.
기존 Datehaja 발신함의 AgentMail 메시지를 다시 조회해 동일한 수신자와 `sent`
상태를 확인했다. 제목은 `[테스트] 리오 · 팝콘값 얘기가 여기까지 왔네`다.
이는 발송 접수 확인이며, 수신함 도착·열람이나 해당 메일 앱의 화면 확인은 아니다.

## 범위와 자료

않는다. 사용자에게 승인받은 한 통의 테스트 발송은 기존 Datehaja 발신함을 사용하며,
가상 테스트 계정의 이메일 알림은 켜지 않는다.

편집 전후와 사실 검증, 실제 발송 페이로드, 모바일/데스크톱 화면, 렌더 검사,
발송 접수 증빙을 함께 보존한다. 자격 증명은 자료에 포함하지 않는다.
