# 6인 로컬 경험 검증 — 2026-09-08

서로 다른 여섯 가상 사용자를 만들고 독립된 인증 세션으로 제품을 사용했다.
대화와 판단은 실제 AI 호출로 생성했고 결과를 강제하지 않았다. 실제 사람이
참여한 사용자 조사는 아니다.

## 환경

- UI `http://127.0.0.1:4174`, 별도 Convex `http://127.0.0.1:3210`.
- 대상: `local-anonymous:anonymous-agent`. 클라우드 개발/운영과 데이터 분리.
- 메일 공급자 자격 증명을 넣지 않았고 모든 테스트 계정의 메일 설정도 껐다.
- 첫 실행을 보관하고 계정을 탐색 대상에서 제외한 뒤, 같은 여섯 성향으로
  재시험했다. 실행마다 활성 참여자 여섯 명, 총 **8개 만남·63개 발화**.
- 초기 실패와 잘못된 판단도 보존했다. 수정된 결과처럼 다시 쓰지 않았다.

## 발견하고 고친 문제

1. 멤버십의 **탐색 시작 버튼이 화면만 이동**했다. 실제 시작 성공 뒤 이동하고
   실패를 표시한다. 접근 상태 조회 실패도 무한 로딩 대신 재시도할 수 있다.
2. 구조화된 **관계 목적이 AI 입력에서 빠졌다**. 각 에이전트에 자기 사용자의
   선택만 전달하고 실제 대화에서 목적을 확인하게 했다. 친절함으로 목적 차이를
   덮거나, 짧은 만남에 관계 전체의 증명을 요구하지 않도록 판단 기준을 조정했다.
3. **끝내겠다고 해도 추가 질문이 붙었다**. `closingAfterRound`를 저장해 한 번의
   작별 뒤 평가로 넘어간다. 추가 발화·연장·오래된 평가가 종료를 뒤집지 못한다.
4. **평가 생성 실패가 일반적인 보류 의견처럼 저장됐다**. 이제 실패를 표시하고
   대화만 보존한다. GPT-4.1 대체 모델에 지원되지 않는 옵션을 보내던 문제와
   평가 출력 예산도 수정했다.
5. **한글 한 글자 이름과 고정된 숫자**를 수정했다. `봄`, `준`, `루`를 만들고
   수정할 수 있으며 `봄야`를 유도하던 예문, `10/6` 기억 수, 여러 언어의 고정된
   여섯 장면 안내를 고쳤다.
6. **메일 없는 로컬 환경에서 개발 OTP 로그인이 UI에 막혔다**. 개발 로그인의
   가용성을 반영했다. 서버의 테스트 이메일 제한과 운영 환경의 발송 설정 요건은 유지한다.

편지도 고정된 “내가 묻고, 상대가 답하고, 아직 모르겠어” 순서를 따르지 않도록
조정했다. 거절 편지에 상대의 의사를 바꿀 여지를 의무적으로 덧붙이지 않는다.

## 검증 근거

- 여섯 계정 모두 멤버십 버튼 한 번으로 실제 검색 상태 생성.
- 첫 실행에서 첫 사람만 동의했을 때 상대의 답·연락처 비공개. 두 번째 사람도
  동의한 뒤에만 양쪽 연락처 공개 및 탐색 종료. 다른 소개를 거절하면 연락처 없이 재탐색.
- 제3자의 다른 만남 조회 거부. 사용자 화면에 상대의 비공개 소감·내부 추론 미노출.
- 데이트별 대화에서 현우가 정정한 “조용함은 무관심이 아니다”가 자기 에이전트의 기억에 반영.
- 하나의 일시정지·새로고침·재개 뒤에도 언어 조건 유지, 만남 0건.
- 여섯 계정의 390px 모바일 대시보드 가로 넘침 없음.
- 실제 저장된 한국어 소개 편지의 390px 렌더링, 모든 그림 로딩, 가로 넘침 확인. 발송 없음.
- **단위 테스트 252개/33파일, 타입 검사·빌드·린트 통과.** 이번에 기존 전체 E2E 묶음을
  재실행했다는 뜻은 아니다. 별도의 6인 브라우저 시나리오를 실행했다.
