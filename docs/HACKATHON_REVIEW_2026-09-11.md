## 우선 수정할 사항

### P1 — 제출용 운영 앱에서 자기 에이전트를 데이트에 보낼 수 없음

`bunx convex env get --prod DATEHAJA_DEMO_BILLING`은 운영 `merry-bass-190`에 해당 변수가 없다고 반환했다.
[billing.ts](../convex/billing.ts)의 `scoutAccessFor`는 이 값이 `1`일 때만 권한을 주며,
그 외에는 모든 사용자에게 `allowed: false, mode: locked, configured: false`를 반환한다.
실제 탐색과 명시적 가상 데이트 요청 모두 이 권한을 검사한다.
[MembershipPage.tsx](../src/pages/MembershipPage.tsx)의 잠긴 상태 버튼도 비활성화된다.

이는 운영 환경 조회와 배포된 코드의 결합으로 확인한 차단점이다.
이번에 새 운영 계정으로 OTP부터 가입 전체를 재실행한 것은 아니다.
그러나 현재 제출 URL에서 누구나 전체 기능을 체험할 수 있다는 주장은 성립하지 않는다.

**완료 기준:** 결제를 열지 않는 별도의 해커톤 체험 권한을 마련하고, 제출 URL에서
새 계정으로 브리핑 → 가상 데이트 → 개인 회고까지 완료한다.
기존 개발용 결제 플래그를 운영에 복사하는 것을 제품 결정으로 대신하지 않는다.

### P1 — 첫 공개 데이트가 오래되고, 가장 강한 학습 증거는 한국어 전용

[운영 /watch](https://merry-bass-190.convex.site/watch)의 공개 쿼리가 반환하는 기록은
2026-09-03 23:06:59 UTC에 끝난 한국어 6턴 데이트다. 활동 기록은 없고 두 판정은 모두 `curious`다.
화면은 영어인데 대화와 개인 회고는 한국어이며, 여섯 번째 발언이 다시 자기소개로 시작한다.
실제 브라우저에서도 재생 버튼과 저장 대화, 두 관점 전환 UI를 확인했다.
비매칭 결말 자체는 결함이 아니다. 오래된 대화가 현재 품질을 대표하는 점이 문제다.

[학습 증거 화면](https://merry-bass-190.convex.site/preview/agent-coaching)은
네 데이트·56마디·세 피드백·누적 기억·복구된 회고를 보여주는 더 강한 자료다.
그러나 [AgentCoachingPreviewPage.tsx](../src/pages/AgentCoachingPreviewPage.tsx)는
`usePreviewLocale("ko-KR")`로 페이지 전체를 한국어로 바꾼다.
랜딩 링크에는 한국어 시연이라는 표기가 있어 숨긴 것은 아니지만, 영어 심사자의 이해에는 장벽이다.

**완료 기준:** 최신 생성기로 영어 가상 인물의 데이트를 기록하고, 같은 소유자의 수정이
다음 데이트 발언에 반영되는 전후 비교를 영어로 읽을 수 있게 한다.
원래 기록과 판정은 보존하고, 번역은 번역으로 명시한다.

### P1 — 전체 흐름 E2E가 현재 UI와 맞지 않음

전체 E2E는 가입·동의·온보딩·개발 체험 권한·탐색 시작까지 진행했으나,
[full-flow.spec.ts:185](../tests/e2e/full-flow.spec.ts#L185)의 `Juno's private room` 그룹 검사에서 실패했다.
실제 대시보드에는 `Your Dating Agent's world`가 있다. 이 실패를 제품 전체 장애로 해석하지 않는다.

뒤쪽에도 도달 불가능한 단계가 있다. 테스트는 탐색을 시작한 채 가상 데이트 버튼을 누르려 하지만,
[AgentDashboardPage.tsx:455](../src/pages/AgentDashboardPage.tsx#L455)는 탐색 중 그 버튼을 숨긴다.
현재 CI는 의도적으로 E2E를 실행하지 않으므로 이 문제와 CI 성공은 양립한다.
혼자 체험하는 사용자도 빈 탐색을 먼저 멈춰야 데모 진입 버튼을 발견할 수 있다.

**완료 기준:** 현재 사용 흐름을 반영해 전체 E2E를 고치고 실제 회고·동의까지 실행한다.
성공 여부와 무관하게 `finally`에서 그 테스트의 탐색을 중단한다.
빈 풀에서 가상 체험으로 넘어가는 UI도 설명 없이 발견할 수 있어야 한다.
이번 실패가 남긴 계정은 별도 개발 API 점검에서 메일을 끄고 탐색을 중단했다.

### P2 — Firecrawl의 실제 역할과 제출 설명이 어긋남

[agentDates.ts:943](../convex/agentDates.ts#L943)에서 장면과 상황은 공통 관심사로 먼저 정해진다.
그 다음 Firecrawl 검색 결과 중 하나를 골라 제목과 URL을 대화 프롬프트에 추가한다.
따라서 “Firecrawl이 실제 장소를 골라 세계를 만든다”는 제출 초안의 설명은 현재 구현보다 강하다.

공개 리플레이의 저장 출처는 영화에 관한 일반적인 Facebook 영상이다.
API는 `worldSourceUrl`을 반환하지만 [WatchPage.tsx](../src/pages/WatchPage.tsx)는
이를 링크로 렌더링하지 않고 장면 컴포넌트에 제목만 전달한다.
심사자가 실제 검색 출처와 대화에 미친 영향을 앱에서 확인하기 어렵다.

**완료 기준:** 실제 역할에 맞춰 제출 설명을 고치고, 출처 제목·링크와 그것이 대화에
어떤 소재를 제공했는지 한 가지 구체적 사례를 보여준다.
AgentMail도 테스트 통과와 실제 받은편지함 도착을 구분해야 한다.
이전 [메일 경험 검증](EMAIL_EXPERIENCE_REVIEW.md)에 Gmail 스팸 분류 이력이 있으며,
이번에는 새 메시지를 보내거나 운영 메일 수신을 재검증하지 않았다.

### P2 — 실제 이용 가치와 배포 이후 반응의 증거가 부족함

운영 `growth:funnelSnapshot {}`을 읽은 전체 기간 집계이며 모든 항목은 잘리지 않았다.

| 이벤트 | 고유 식별자 수 |
| --- | ---: |
| 랜딩 방문 | 28 |
| 온보딩 시작 | 1 |
| 에이전트 생성 | 1 |
| 개인 메시지 전송 | 0 |
| 데이트 요청 / 완료 | 각각 1 |
| 회고 대화 / 사람 동의 / 연락처 공개 | 각각 0 |

랜딩 이벤트는 36건이며 출처는 direct 29건, watch 7건뿐이다.
방문 식별자는 실제 사람 수가 아니고 기존 검증 트래픽이 섞여 있다.
유일한 완료 데이트는 공개용 가상 기록이므로 실제 사용자의 성공 경험으로 세지 않는다.
이 작은 표본으로 전환율을 평가하거나 외부 사용자가 전혀 없다고 단정하지 않는다.

**완료 기준:** 독립적인 사용자 3–5명이 설명 없이 시작하고,
“이 발언은 나답다/나답지 않다”를 지적한 뒤 다음 데이트의 변화를 확인한다.
허락받은 짧은 후기와 실제 완료 수를 제출 근거로 남긴다. 가상 사용자 검증과 분리한다.
